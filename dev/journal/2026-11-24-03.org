* 04:50 :issue-249:contrib-pool:allocation:
AMD sequential under-predicted by 0.5% (9.317 vs 9.364 GB). Cause: the
single-slot contribution pool. assemble_children puts each consumed child's
buffer in the pool; extract_contrib reused it with clear()+reserve(len), so
a block kept a larger recycled buffer's capacity (pinned until its parent),
and a smaller one was realloc'ed (moved: no saving) and doubled. Simulating
that exactly gave 9.528 (bounds). But for the parallel model, which buffer a
worker recycles depends on the schedule, so no bound below 2x the largest
block existed. Fix: recycle only when len <= cap <= len + max(len/8, 512),
else allocate exactly. Values unchanged (bit-exact); block capacity <=
1.125 len + 4 KiB, which the model now uses.

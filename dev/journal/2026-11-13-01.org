* 18:38 :issue-232:markowitz:pivot-order:determinism:
Lazy heap holds duplicate *live* (c, j) copies (re-push without a count
change, or count returning to an earlier value). The search pops each
copy, rescans the column and counts it again against max_search = 8.
So "build heaps over the kernel only" cannot be bit-identical to the
old code: multiplicity is push-history dependent. Measured: adding only
a per-step scan_mark dedup to the old code changes digests on 5/6 bases
(all but QPLIB_3852). Decision: dedup (count distinct columns, as the
Suhl cutoff is meant), then require the refactor be bit-identical to
"old + dedup". Fill cost of the dedup, 40 synthetic seeds: geomean
+0.27 %, min -0.46 %, max +1.61 %, 36 worse / 4 better. QPLIB_1157
51254 -> 51532 (+0.54 %); QPLIB_3852 and bchoco06 unchanged.
Consistent small direction, not explained; plausibly tie-breaks
(cost-equal candidates prefer larger |v|, which is not fill-aware).

* 14:35 :issue203:structure:
Read the reproducer's index arithmetic to recover the actual graph.
`NS=775` states per collocation point, `NCP=3` points per element,
`NC=6` controls with one knot per element, `NE=6` path constraints per
point. The embedded spatial coupling `S` is 775x775 with **1977**
nonzeros — 2.55 per row, i.e. a near-tree network (GasLib-40, 10 finite
volumes per pipe), not a dense block.

So the graph is not a chain of dense blocks. It is a **2-D product**:
a sparse spatial network of 775 nodes crossed with a time path of
`3*nfe` points, with the constraint rows roughly doubling each slice.
Spatial extent 775 is *larger* than the temporal extent `3*nfe` for
every size tested (18 at nfe=6, 288 at nfe=96, 648 at nfe=216). The
premise "1-D chain with linear-fill elimination available" does not
hold at these sizes: a time-slice separator is 775 states wide, and
densifying it costs 775^2/2 ~ 3e5 per cut.

* 16:45 :issue203:metis:diagnosis:
Read `crates/feral-metis/src/node_nd.rs::multilevel_node_bisection`
against METIS 5.x `ometis.c`/`refine.c`. feral does:

  coarsen -> niparts edge bisections at coarsest -> uncoarsen refining
  the **edge cut** at every level -> `construct_separator` (Konig min
  vertex cover) once at the finest level -> one greedy
  positive-gain-only `refine_separator` pass.

METIS does:

  coarsen -> `InitSeparator` (edge bisection + `ConstructSeparator`) at
  the **coarsest** level -> `Refine2WayNode`: at every uncoarsening
  level project the **node separator** down, `FM_2WayNodeBalance`, then
  `FM_2WayNodeRefine1Sided/2Sided` for `niter` passes — real FM with
  gain buckets, negative-gain moves and rollback to the best state seen.

Two concrete gaps: (a) the refinement objective during uncoarsening is
the edge cut, not the separator weight; (b) the one separator pass that
does run is hill-climbing-free greedy, so it stops at the first local
minimum — which is why `fm_passes=200` changes nothing. Note
`refine_separator` at `fm_refine.rs:214` only accepts `best_gain > 0`.

Next: implement node-separator FM and move it into the uncoarsening
loop. Research note and plan before code.

* 19:10 :issue203:wallclock:measure:
Ran the wall-clock half of "next session item 1" that is runnable here.
`data/matrices/` holds **2** synthetic matrices on this machine, so the
corpus-wide re-decision of #67/#73 is still blocked; what *is* runnable

The reproducer emits pattern only (diag 4 / offdiag 1), which is not a
saddle point and so drives none of the pivoting a real KKT drives.
`value_kkt.py` keeps the pattern and assigns block-aware values:
`K = [[H, J^T], [J, -dI]]`, `H` strictly diagonally dominant positive
(SPD), `d = 1e-2`. Inertia is then analytically `(n_vars, m, 0)` with
**no rank assumption** — the Schur complement `-dI - J H^-1 J^T` is
negative definite whatever `J` is. That is the correctness gate.

New harness `issue203_ab`: four ordering arms in one process against
one matrix and one RHS, paired alternating, 7 pairs, `min` per arm,
exact two-sided sign test, correctness gate printed before any timing.
All arms hit the inertia oracle exactly at every size, `rel_res` 9e-15
to 2e-14.

* 19:20 :issue203:wallclock:finding:
Two things the symbolic work got wrong, both now measured.

1. **The flop model underestimates, badly.** Predicted 1.62x / 1.74x at
   nfe=48/96; measured 3.52x / 3.70x. `sum_j (c_j-1)^2` is the right
   shape but not the right magnitude.
2. **At nfe=24 the flop model has the sign wrong.** It said `Amf`
   (1.83e9) beats `metis` (3.05e9) by 1.67x. Measured, `metis` is
   *faster* by 1.12x (6/7, p=0.125 — not significant, but certainly not
   the 1.67x loss predicted). So `MetisND` is at worst neutral and at
   best 3.7x at every size measured here.

Third, unlooked-for: **`Amd` beats `Auto`/`Amf` by 1.63x at nfe=96**
(1496 ms vs 2442 ms, 7/7, p=0.0156) despite 15% *more* fill (53.7M vs
46.4M). Another instance of the same lesson the repo already recorded
on nql180 — fill does not predict speed — and a hint that `Auto`'s
preference for `Amf` over `Amd` at large n is itself unexamined on this
class.

**What this does and does not license.** It licenses saying the ordering
fix reaches the clock on the #203 class, with a measured 3.5-3.7x on
numeric factorization at the sizes pounce runs. It does **not** license
changing `choose_adaptive`: #67/#73 decided the blanket
`MetisND -> Amf` reroute over 36+ families on a corpus this machine does
not have. Three matrices are a counterexample, not a refutation.

But the counterexample matters more than usual, because **#67/#73 were
measured against the old feral-metis** — the one that was 2.4-3.5x worse
than it should have been. Their evidence base is not merely incomplete
for this class; it is stale for every class. Re-running that A/B with
the new METIS should be treated as required, not optional.

Caveat on all of the above: `H` here is strictly diagonally dominant, so
pivoting is easy and delayed pivots are rare. A real IPM KKT gets harder
as mu -> 0. The direction is solid; the magnitude is a hypothesis about
the real matrices.

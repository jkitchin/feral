* 11:40 :issue-215:cascade-break:warm-state:design:
Implemented auto re-analysis on cascade-break (user-chosen fix). Gate:
pattern_reused && resolved_preprocess == LdltCompress && n_cascade_break_nodes
> 0 && miss latch < 2. Action: re-run symbolic with the Step-3 config
(LdltCompress forced if escalated), refactor with the same effective params,
keep the new factor iff (cb, tfa+tiny) is lexicographically smaller; the
incumbent keeps exact ties. Counters auto_reanalyse_count / _adopted_count,
opt-out with_auto_reanalyse_on_cb(false).

Unit fixture: paired_blocks(n, shift), tridiagonal sum of [[eps,1],[1,eps]]
blocks with delta=1e-3 coupling; shift moves the pairing by one. Inertia
(n/2, n/2, 0) by Weyl (perturbation eps+2delta < 1). Stale analysis simulated
by zeroing delayed_capacity of the cached symbolic after a shift=false factor.
Without re-analysis the shift=true refactor engages CB (asserted); with it,
one re-analysis is adopted, CB 0, inertia exact.

A natural small reproducer did not exist: a 600x600 KKT with the matching
flipped between factors gave cb 0 both times (examples/cbprobe215.rs, not
committed), so the capacity-zeroing simulation is used instead.

Stats bug confirmed and fixed: the escalation re-entry keeps the
fingerprint, so pattern_reused read true on a fresh Solver's first factor.
factor() -> factor_impl(.., reentry_pattern_reused); escalation passes the
outer value. pattern_reused_hint (permute cache) still uses cache_valid;
that cache validates perm_inv, so a changed analysis cannot reuse a stale
permutation. Regression assertion added to tests/issue102_ordering_escalation
(cont5 fixture, SKIP when absent); mutation check: reverting the fix makes it
fail with "first factor on a fresh Solver reported pattern_reused = true".

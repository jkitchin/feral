Three conclusions:

1. =Pivot selection is perfectly stable under uniform shift=.
   λ(A + αI) = λ(A) + α algebraically, and feral's reported inertia
   tracks it bit-perfectly: 12498 → 12382 → ... → 0 as α grows
   from 0 to 1e20.

2. =The instability is intrinsic to the structured x-block shift=,
   and it appears in *all three* configs — including =PerturbToEps=
   which bypasses the zero-pivot branch entirely. So the
   strict-zero accounting fix (commit 94a28bc) was correct but
   addresses a different concern; it does *not* fix the cascade
   monotonicity issue pounce is observing.

3. =MA57-style pivot_threshold = 0.01 does not help=. Actually
   slightly worse (6 vs 3 Weyl violations). Threshold pivoting is
   not the lever.

Phase-transition signature: large neg jumps at α=1e2 (+150 to +189)
and α=1e16 (+422 to +464) regardless of config. These are
deterministic BK 1×1-vs-2×2 acceptance flips where the shifted
diagonal magnitude crosses one of feral's growth-bound thresholds.

Hypothesis for root cause (not yet confirmed):
- Feral's dense BK kernel ranks 1×1 vs 2×2 pivots using local
  magnitudes. When only some rows are shifted, the global
  ranking is structurally different from the uniform case, and
  feral picks a different pivot order that yields a different
  Sylvester signature for the trailing matrix. This is
  algebraically wrong only insofar as the *trailing matrix's*
  inertia differs from the original (it does — by Schur).
- SSIDS / MA57 may handle this via more aggressive delayed-pivot
  strategies (push the small/uncertain pivot into the contribution
  block and try later in a larger frontal context). Feral has
  =allow_delayed_pivots= but maybe its threshold is too tight for
  IPM cascade shifts.

Next investigation step (queued, not in this session): MA57
head-to-head on the same α-sweep. If MA57 also jitters under
structured shift, this is intrinsic to dense BK and the fix is a
different KKT regularization strategy (e.g., the IPM should
constrain its δ ladder to per-block-balanced shifts, or use
ill-conditioning detection differently). If MA57 stays monotone,
feral's BK has a fixable ordering bug.

Findings:

1. =Iterative refinement does not rescue= the x-block-shifted
   factor. At α=1e16 IR gives identical residual to unrefined.
   The factor is too inaccurate to bootstrap IR (Skeel
   condition number κ̂ exceeds 1/ε on this matrix). IR only
   shaves an order of magnitude at small α and is useless once
   the matrix becomes ill-conditioned by structured shift.

2. =Default pivot_threshold = 1e-8 reproduces pounce's
   cascade=. At α=0 (no shift): inertia (13441, 12498, 710),
   neg+zero = 13208, rel_resid = 7.7e5 — matches the
   previously-reported probe_issue54 default config exactly.
   This =is= what pounce is running, so the cascade
   non-monotonicity isn't a configuration mismatch.

3. =pivot_threshold = 0.01 (MA57 default) helps in the IPM
   δ_x ≤ 1e4 regime= — residuals drop 12+ orders of magnitude
   (e.g. α=1: 2e19 → 1.7e3). It does =not= help at
   α ≥ 1e16 where dynamic range 1e16:0 exceeds f64 precision.
   Inertia accuracy is slightly worse (more delayed-pivot
   uncertainty pushed to the `zero` bucket).

4. =Phase transition at α=1e2 is universal=: every config
   shows a sharp shift in inertia and/or residual around
   α=1e2. This is the diagonal magnitude where BK's
   intra-supernode pivot ranking changes; the growth-bound
   threshold scales with col_max, and shifted diagonals
   crossing col_max trip a different pivot ordering.

Bottom-line interpretation:

- =The factor is the bottleneck=, not the inertia counter
  (commit =94a28bc= already fixed counting). IR can't bridge
  the gap because the factor's intrinsic forward error is too
  large.
- =No single pivot_threshold value covers the full δ_x
  cascade=. Small thresholds break early (more 1×1 pivots
  accepted as huge), large thresholds break late (still 1e17+
  residual at α=1e16). Pounce's IPM cascades through both
  regimes by design.
- =At α ≥ 1e16, the factor is unrecoverable in f64=. Any
  IPM that bumps δ_x to 1e16+ is asking BK to factor a
  matrix with 1e16:0 diagonal dynamic range, which is
  inherently beyond machine precision. Real solvers handle
  this by =never reaching that regime= — they regularize
  before it becomes catastrophic (MA57 caps δ_x growth
  earlier; SSIDS uses delayed-pivot escalation).

Concrete recommendation for the IPM caller side (pounce):
- Cap =δ_x= at ≈ ||A||_∞ × 1e4 rather than 1e20. Beyond
  that bound, no dense direct solver gives reliable inertia.
- Use a tolerance on inertia equality: =|neg+zero −
  expected| ≤ max(10, 0.005·n)= rather than strict equality.
  The corpus consensus framework already uses this regime.

Concrete recommendation for the feral side (queued, task #10):

  give the cascade more numerical room.
- Run MA57 head-to-head on this α-sweep to determine whether
  the gap is fixable in feral's BK kernel or whether all

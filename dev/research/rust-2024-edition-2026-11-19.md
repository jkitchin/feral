# Rust 2024 edition + resolver v3 + MSRV (issue #147)

## Scope

All nine crates move from edition 2021 to 2024 in one change: the eight
workspace members (`feral`, `feral-ordering-core`, `feral-amd`,
`feral-amf`, `feral-metis`, `feral-scotch`, `feral-kahip`,
`feral-diagnostics`) and the separate `python/` workspace
(`feral-python`). Workspace resolver 2 → 3. Declare
`rust-version = "1.85"` (user decision, 2026-11-19).

## Effect on downstream crates (pounce, Ipopt shim, Python)

- **Editions are per crate.** A 2021-edition dependent (pounce) can use a
  2024-edition feral unchanged. Resolver v3 only governs resolution in
  feral's own workspaces; dependents use their own resolver.
- **The one downstream effect is the compiler floor.** Edition 2024 needs
  rustc ≥ 1.85 (Feb 2025). Before this change the `feral` library's
  normal-dependency tree needed about 1.80 (its highest declared
  `rust-version` is rayon 1.11's 1.80). `clap` (1.85, edition 2024)
  already appears in the workspace via the tools crates, not in feral's
  library tree. Toolchains seen in recent issues: 1.92 (#237), 1.93.1
  (#211), CI stable.
- **Release as 0.24.0.** A pounce release that depends on `feral = "0.23"`
  keeps resolving 0.23.x and never sees the floor change. Shipping in a
  0.23.x patch would push 1.85 onto older pounce builds via
  `cargo update`.
- **C ABI unchanged.** `#[no_mangle]` becomes `#[unsafe(no_mangle)]`;
  symbol names and calling convention are the same, so
  `feral-ipopt-shim` and the Python wheel link as before. Checked by
  comparing the exported `feral_*` symbols of `libferal.a` before and
  after.
- **Numerics unchanged.** An edition does not change floating-point
  semantics. Checked by the harness solve digests
  (`examples/issue237_permute_warm.rs`) before and after, and the full
  test suite.

## Edition-2024 changes that can touch this code

- `unsafe` attributes / `unsafe extern`: `src/capi.rs` (11 exported
  functions). `cargo fix` rewrites the attributes; reviewed by hand.
- `unsafe_op_in_unsafe_fn` is warn-by-default: unsafe operations inside
  `unsafe fn` bodies need explicit `unsafe {}` blocks, each with a
  safety comment (CLAUDE.md hard rule).
- Temporary scopes in `if let` scrutinees and block tail expressions:
  temporaries drop earlier. Matters only for values with side effects on
  drop, such as `MutexGuard` in the parallel driver; the effect is a lock
  released earlier. Borrow problems are compile errors, not silent.
- RPIT lifetime capture, never-type fallback, `gen` keyword reservation,
  `expr` macro fragment, `Box<[T]>: IntoIterator`, prelude additions
  (`Future`, `IntoFuture`): handled or flagged by `cargo fix --edition`.

## MSRV enforcement

`rust-version = "1.85"` in every crate (one value, via
`[workspace.package]` where possible), and a CI job that runs
`cargo check` on toolchain 1.85 for the published crates (library and
tests). Without the job, the declaration would not be checked.

  crate is a member but **not** a dependency of `feral`, root commands

- **Verification** (all green):
  - root `cargo build`: no diagnostics compiled.
  - `cargo build -p feral-diagnostics`: all 144 compile, **zero warnings**

## Decisions Made
- **Diagnostic binaries live in a non-default workspace crate (#71)** —
  appended to `dev/decisions.md`. Separate crate chosen over per-bin
  `required-features` gating (which would force disabling `autobins` and
  enumerating 144 `[[bin]]` blocks). `bench.rs` kept in root; CI keeps the
  diagnostics lint/test-gated on Linux.

## Abandoned Approaches
- Initial `feral-diagnostics/Cargo.toml` listed only `feral-ordering-core`
  and `feral-metis` as ordering deps (from a line-anchored `^use` scan that
  missed indented `use feral_amd` inside fn bodies). `cargo build -p
  feral-diagnostics` failed with `E0433/E0432: unresolved crate feral_amd`
  (diag_amd_substages). Fixed by adding all six ordering crates as path
  deps. (Not a code-design dead-end — a manifest omission caught by the
  build; noting it so the `^use`-only scan pitfall is on record.)

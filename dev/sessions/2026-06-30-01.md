# Session 2026-06-30-01

## Goal
Investigate issue #91 ("catastrophic factorization slowdown on a QAP-style
KKT vs faer, 12s → 0.2s") and — per the user's direction — *fix* feral so it
is fast on this matrix, in pure Rust.

## Accomplished
- **Reproduced the exact matrix.** Generated the qap15 conic-IPM KKT via
  pounce-convex + `POUNCE_DBG_KKT_DUMP` (parse qap15.mps with HiGHS → LP →
  `pounce.qp.solve_qp`). Matches the issue byte-for-byte: dim=50880,
  nnz=168105. Quasi-definite (22275 tiny-positive diagonals ~1e-10, 28605
  negative, 0 zero).
- **Root-caused the slowdown** with a measurement harness
  (`examples/bench_qap15.rs`). It is *not* AMD quality, amalgamation, delayed
  pivots, or the dense kernel — all were measured and refuted:
  - `nnz_L` identical (40.9M) across default / +fma / static_pivot → not
    delayed pivots.
  - `nemin` 1 vs 16 → identical simplicial fill → not amalgamation.
  - feral AMD simplicial fill with `preprocess=None` = **7.16M**, *below*
    faer's 13.4M → AMD ordering is excellent.
  - The culprit: `OrderingPreprocess::Auto` (`pick_ordering_preprocess`,
    src/symbolic/mod.rs) fires MC64 `LdltCompress` when ≥30 % of columns have
    ≤2 nonzeros — which a regularized quasi-definite IPM KKT has in abundance.
    On qap15 that compression inflated simplicial fill **7.16M → 45.4M (6.3×)**
    and factor time **0.77 s → 15.4 s (20×)**.
- **Fixed it.** `OrderingPreprocess::Auto` now *verifies* rather than predicts:
  when the predicate recommends `LdltCompress`, run the symbolic pipeline both
  ways and keep `LdltCompress` only if it does not inflate fill past 2× the
  `None` baseline (`PREPROCESS_FILL_INFLATION_LIMIT`, new
  `symbolic_factorize_preprocess_auto`). qap15 default factor **15.4 s → 0.77 s
  (20×)**, nnz_L 40.9M → 9.25M, inertia (+22275,−28605,0) unchanged.
- **Regression guard.** `tests/issue91_preprocess_misfire.rs` + gitignored
  fixture `tests/data/large/qap15_kkt.mtx` + `dev/scripts/regen_qap15_kkt.sh`
  / `gen_qap15_kkt.py`.
- Full corpus suite green (68 `test result: ok`, 0 failed); fmt + clippy clean.

## Decisions Made
- `OrderingPreprocess::Auto` resolves by verified fill race with a 2×
  catastrophe ceiling, not structural prediction. Appended to
  `dev/decisions.md` (2026-06-30 entry).

## Abandoned Approaches
- "Smaller-fill-wins" Auto race (keep LdltCompress only on ties/improvements):
  regressed inertia on near-singular KKTs (twirism1, sawpath) because
  LdltCompress's MC64 2×2 pivots give the oracle-correct inertia at a modest
  fill cost. Appended to `dev/tried-and-rejected.md`.

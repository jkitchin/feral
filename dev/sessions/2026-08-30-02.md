### PR #191 -- reviewed, fixed, merged (f1dc5ee)

Eight review findings, all verified against the source before acting, all
fixed. Two were material:

1. **`backward_error` returned `0.0` on a non-finite iterate**
   (`src/numeric/solve.rs`). `NaN` loses every `>` comparison, so a row
   whose `term` was `NaN` was silently skipped; an overflowed iterate makes
   *every* row `NaN` (`x -> inf`, so `|A||x|` and `|r|` both reach `inf`
   and the ratio is `NaN`), and the function returned `omega = 0.0` -- a
   diverged solve certifying itself as exactly backward stable. Under
   `StopCriterion::BackwardError(t)`, which #191 newly exposes, `reached()`
   is then true on the first test: the loop breaks immediately and returns
   `RefineStop::Converged` with a garbage iterate and
   `relative_residual = NaN`. Confirmed by removing the guard:

   ```
   non-finite iterate [inf, 1.0] must report inf, got 0e0
   ```

   Fixed by returning `f64::INFINITY` for any row where `d` or `r[i]` is
   non-finite. `EpsSqrtN` never had this hole (`NaN < threshold` is false,
   so refinement keeps running) and the shipped default conjunction is
   covered by its normwise half, so the exposure was the bare
   `BackwardError` option a caller would be opting into.

   as converged" paragraph still said `RefineOptions::default()` "keeps

### The downstream omega question -- answered by extending the type

The comment on #191 asked whether `RefineOutcome` carries the achieved
residual / omega as well as the step count. It carried the residual only.
Rather than answer "no, file it for 0.19.0", `backward_error: f64` was
added (be1e234): omega was already computed at every construction site and
thrown away, `RefineOutcome` is new and unreleased so the field costs no
additional break, and 0.18.0 is the release that makes omega *the quantity
the default criterion certifies*. Returning `Converged` without exposing
the certificate -- or forcing a second `abs_symv` to recompute it -- was
the wrong shape.

The sharp edge, documented and answered in the reply: omega is only formed
when it is the criterion. Under `EpsSqrtN`, `RelativeResidual`, and
`max_steps = 0` the field is **`NaN`, meaning not measured** -- deliberately
distinct from `INFINITY`, which is a real measurement of a non-finite
iterate. Consumers must guard with `!o.backward_error.is_nan()`, since a
bare `>` comparison reads `NaN` as "fine".

### PR #195 -- reviewed, one defect found and fixed, then landed

The mechanism was checked and holds up: ordering escalation
(`src/numeric/solver.rs:1558`) sits on the `Ok` path so `Interrupted`
cannot drive the recursive re-`factor`; and `run_parallel_task`'s
`task_res = Err(..); break` lands in the pre-existing `Err` arm
(`src/numeric/factorize.rs:3919`), which sets `first_error` and skips the
parent enqueue -- and it is a `break`, not a `return`, so the
`local_contribs` restore into the workspace still runs.

**The defect: the issue-#65 MC64 rescue swallowed `Interrupted`, and
latched.** The non-adoption arm was a bare `_`, so it also caught `Err(_)`:

```rust
match retry {
    Ok((rf, ri)) if ri.zero < first_zero => { /* adopt */ }
    _ => { mc64_retry_not_adopted_now = true; Ok((factors, inertia)) }
}
```

Two consequences. `factor` returned `Success`/`Singular` instead of
`Interrupted`, contradicting the contract the branch publishes. And
`mc64_retry_not_adopted` latched -- a latch keyed on the *pattern* and
cleared only on a pattern change (`src/numeric/solver.rs:1038`), so an
interior-point host, which refactors a fixed pattern for a whole solve,
would have the issue-#65 rescue suppressed for every remaining iterate by
one unrelated cancellation.

The second is the serious half, and it is a hard-rule violation, not a lost
optimization. The field's own doc (`src/numeric/solver.rs:252-273`) already
flags the latch as interacting with the inertia constraint: suppressing the
retry reports "unrescued inertia where the pre-latch code recovered." That
doc reasons about the latch being armed by a *genuine* non-adoption, where
"MC64 did not help" is real evidence. A cancellation gathers no evidence at
all -- the retry never finished. So cancelling a factorization, which the
branch correctly describes as leaving no trace beyond invalidated factors,
could instead produce wrong inertia for the rest of a solve.

I initially called this a race. It is barely one: the vulnerable window is
the entire duration of the retry -- a second full factorization of the same
matrix -- i.e. exactly the long-factorization case issue #194 exists to
interrupt.

Fixed by one arm before the `_`, propagating `Err(FeralError::Interrupted)`
and leaving the latch disarmed.

## Checked and cleared

Mid-review I flagged `needs_refinement`'s new `multiplier_bound` as a
possible unintended tightening -- reading `1/pivot_threshold` as roughly
100 and concluding the flag would now fire on vastly more factorizations.
That was wrong in both direction and premise. The default
`pivot_threshold` is `u = 1e-8`, so `1/u = 1e8`, which is two orders
*looser* than the old flat `1e6`: the flag fires on strictly **fewer**
factorizations at the default, which is exactly what the CHANGELOG entry
claims ("far fewer spurious `true`s on badly-scaled systems"). The bound
only tightens below `1e6` once `increase_quality` has walked `u` past
`1e-6` towards `pivtol_max = 0.5`, and tightening the signal as the
promise tightens is the stated intent. The change is documented under
"`needs_refinement` now measures growth against the pivot threshold, not a
fixed 1e6" and covered by four cases in `growth_flag_tests`. No action
needed.

## Decisions Made

- **`RefineOutcome` carries `backward_error`, with `NaN` reserved for "not
  measured" and `INFINITY` for a measured non-finite iterate.** The two must
  stay distinguishable: collapsing them would make an unmeasured path
  indistinguishable from a diverged one, and `NaN` failing every comparison
  is what makes the unmeasured case fail *safe* only if consumers guard on
  `is_nan()`. Documented on the field.

- **A cancellation is not evidence about MC64.** `mc64_retry_not_adopted`
  may only be armed by a retry that ran to completion and genuinely failed
  to reduce the zero count. Any error out of the retry -- `Interrupted`
  today, and by the same argument any future error variant -- leaves the
  latch disarmed. The latch is a cache of a *measurement*; arming it without
  one is a correctness bug because the latch gates the inertia rescue.

## Abandoned Approaches

- **Warming the symbolic cache before the #195 interrupt test**, the
  convention the PR's own eight tests use. Warming requires a `factor()` on
  the singular pattern, which arms the very latch under test, and there is
  no public API to clear it. Replaced with calibrate-then-sweep.

- **`thread::sleep` as the test watchdog.** ~1 ms granularity and it
  overshoots, against a ~6 ms call; with seven coarse fractions no attempt
  ever landed in the window and the test failed its own vacuity guard.
  Replaced with a `std::hint::spin_loop()` busy-wait over 61 fine steps.

- **A landing detector keyed on `status == Interrupted`.** That is precisely
  the observable the bug swallows, so pre-fix it could never report
  "landed" -- it would have misreported a live bug as "never exercised" and
  passed the fix off as untested. Replaced with two fix-independent
  observables: `mc64_retry_attempt_count() == 1` proves factorization #1
  returned `Ok(..)` (the gate keys on `Ok`), and `delay < call_elapsed`
  proves the flag was set before the call returned; together they pin the
  flag inside the retry without referencing the status being asserted.

- **A busy-wait shell poller (`until ...; do :; done`)** run alongside a
  live benchmark. Contaminated the measurement -- see the note at the top.

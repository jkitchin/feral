## Accomplished

### (a) B2 cache bug — FIXED, committed `86fb953`

Root cause: `compute_infnorm` (`src/scaling/infnorm.rs`) returns
`ScalingInfo::Applied`, byte-identical to the MC64-complete `Applied`.
The B2 population gate was `matches!(scaling_info, Applied)`, so on an
InfNorm-routed matrix B2 cached the **InfNorm** vector and re-injected a
*stale iter-k* InfNorm scaling as `ScalingStrategy::External` on the
next warm `factor()`.

Fix (`src/numeric/solver.rs`): added an `mc64_ran` gate — B2 populates
only when the effective strategy is `Mc64Symmetric`, or `Auto` routing
(via `pick_scaling_strategy`) to `Mc64Symmetric`, **and**
`scaling_info == Applied`. `InfNorm`/`Identity`/`External` never
populate; on a non-MC64 route any prior cache is cleared.

Evidence:
- New test `mc64_cache_does_not_engage_on_infnorm_route_issue_49`
  (factors `tridiag(6,10,1)` 3× on one `Solver`; asserts route is
  `InfNorm`, `mc64_cache_hit_count()==0`, `symbolic_call_count()==1`) —
  fails pre-fix, passes after.
- `probe_cache_sequence` over all 10 dumped ex4_2_320 IPM iterates:
  `mc64_hits` 3/10 → **0/10**.
- All 23 solver tests + full `cargo test` suite green; `cargo fmt` /
  `clippy` clean; pre-commit hooks passed.
- `CHANGELOG.md` `[Unreleased]` updated (`### Fixed — B2 scaling cache`).

### (b) POUNCE-feral cost gap — investigated, premise refuted

The "~40 s/iter" premise is **wrong**. Clean measurements:

| Run | Wall | per-factor |
|---|---|---|
| ex4_2_320 → convergence (17 iters) | 10.6 s parallel / 17.5 s serial | ~0.5 s / ~0.9 s |
| ex4_2_160 → convergence (21 iters) | 2.29 s | ~0.09 s |
| 12-run repeat batch | parallel 10.2–10.8 s, serial 16.9–17.7 s, all exit 0 | — |

Per-factor ~0.5 s parallel is fully consistent with standalone feral
(~0.25–0.3 s warm). There is **no systematic gap** — POUNCE's wrapper
rebuilds `CscMatrix::from_triplets` each `factor()` but the symbolic and
pattern caches stay engaged (`symbolic_calls = 1`).

**The 600 s timeout — retracted as a "reproduced hang."** One uncapped
convergence run timed out at 600 s, last printed line iteration 10. It
did not reproduce: `probe_hang_loop` ran **1000** back-to-back parallel
factorizations of the densest dumped KKT (`ex4_2_320_009`) on one warm
`Solver` — 0 hangs, 0 spikes (median 277 ms); 12 full POUNCE runs — 0
hangs; and a controlled 20× repeat (below) — 0 timeouts. The most
likely explanation: the timed-out run linked the **pre-cache-fix**
feral, whose B2 bug deterministically inflated ex4_2 factorizations and
blew a 600 s budget. Post-fix the same run finishes in ~10.6 s. It was
two different *deterministic* binaries, not one nondeterministic one.
The earlier "intermittent parallel-factorization race in feral" framing
was an overclaim and is retracted.

**No ULP nondeterminism — earlier claim RETRACTED.** An earlier draft
of this checkpoint (and journal §12:10) claimed "ULP nondeterminism IS
present" from four POUNCE ex4_2_320 logs showing iter-4 `inf_pr` as
`7.32e-13` in two runs, `7.33e-13` in two. **That claim is wrong and is
withdrawn.** Those four logs were never produced by an identical
command on an identical binary — they used different POUNCE invocations
(`print_timing_statistics` flag, perl-pipe) *and* almost certainly
linked different feral builds across the `86fb953` cache fix. The cache
bug deterministically alters the factorization, so a pre/post split
yields a stable two-value spread that is **not** run-to-run noise.
Comparing logs across a build boundary and reading the delta as a
floating-point-summation fingerprint was a methodology error: no
identical command was ever run twice before the claim was made.

The controlled experiment — the exact same command, identical binary,
identical args, ex4_2_320 to convergence, **20 times**:

- 20/20 finished 10–11 s, 17 iterations, `Optimal`.
- 20/20 iteration tables **byte-identical** (0/19 differed from run 01).
- iter-4 `inf_pr = 7.33e-13` in **all 20** — no 7.32/7.33 split.
- 0 hangs.

There is no ULP nondeterminism and no hang to track — neither in feral
nor as a POUNCE follow-up. feral factorization is value-deterministic
(structural: no parallel FP reduction; empirical: several thousand
bit-identical repeated factorizations, see
`probe_value_determinism`). POUNCE ex4_2_320 is deterministic.

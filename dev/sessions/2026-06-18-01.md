# Session 2026-06-18-01

## Goal

Review discopt#229 (revised-simplex node LP ~750× slower than HiGHS on the
casctanks McCormick relaxation; root cause attributed to feral's
`SparseLu::update` bump re-triangularization), decide whether/what to implement,
and — once the user opted in — fix it on the feral side.

## Accomplished

**Review + diagnosis (verified against source, rev 5ab8074).** Confirmed the
O(bump²) cost lives in `eliminate_bump` (`src/lu/sparse_update.rs`): a
per-pivot-column scan `for i in k..=h { get_col(u_rows[i], k) }` (lines 321–327)
that probes every bump row regardless of fill, plus the elimination loop.

**Prior-art gate fired.** The "obvious" asymptotic fix — textbook FT cyclic
permutation (Hessenberg, single subdiagonal) — was already tried and **reverted**
(journal 2026-06-08-01.org) for a sparse-U zero-superdiagonal-pivot → division-by-
zero bug; the current in-place partial-pivoting scheme exists to dodge it. Re-scoped
with the user to: ship the correctness-safe optimizations now, park the asymptotic
route as a research spike.

**Reproducer (tests-first).** Extracted the real casctanks LU update trace from
discopt (`claude/root-setup-perf`, `primal.rs` instrumented behind
`FERAL_DUMP_LU_TRACE` in worktree `../discopt-rsp`): m=2169, 36 segments, 1702
updates, avg bump width 574, optimum −167.751. Committed a 3-segment fixture
(`tests/data/lu_trace/casctanks.txt`, 640 K), a correctness guard
(`tests/lu_update_casctanks.rs`: oracle-free true residual + opt-in DenseLu
cross-oracle), and a criterion bench (`benches/lu_update_trace.rs`).

**Step 1 — sub-diagonal pivot index (shipped, 902e5d7).** `col_rows[c-r]` indexes
the bump rows holding a column-c entry, maintained across the partial-pivot row
swap and `row_sub` fill; pivot search + elimination iterate only real entries.
Sorted lists preserve the lowest-index tie-break, so the `FtOp` sequence is
bit-identical.

- Correctness: full-trace replay true residual **1.819e-12 (unchanged)**,
  refactor_signals=0, dense cross-oracle 2.764e-15 (unchanged).
- Speedup: bench 136 ms → 12.3 ms (11×) on the fixture; full 1702-update chain
  2.14 s → 0.22 s release; committed test 4.77 s → 0.22 s debug.
- End-to-end ([patch]-override in discopt, debug): casctanks `solve_lp_py`
  **82.4 s → 5.2 s (15.8×)**, optimum −167.751 unchanged.

**Step 2 — dense bump workspace: REJECTED (2724cd7).** Measured the real bump
density before implementing: wide bumps (>500, 924 updates) are **0.23% dense**
(~24 row_subs/update). A dense workspace would touch ~534k cells vs ~24 sparse
ops — a ~100–1000× regression. Step 2's dense-spike premise does not hold for the
McCormick regime; Step 1 stands alone. Recorded in `dev/tried-and-rejected.md`.

## Decisions Made

- For the McCormick LP regime, the sparse FT bump update is fixed by the
  sub-diagonal pivot index (Step 1) alone. Dense workspace (Step 2) rejected;
  cyclic-permutation / sparse-BGR asymptotic route remains a parked research
  spike. (See `dev/decisions.md` 2026-06-18.)

## Abandoned Approaches

- Step 2 dense bump workspace — regresses the wide-but-ultra-sparse McCormick
  bumps. Full rationale + density data in `dev/tried-and-rejected.md` 2026-06-18.

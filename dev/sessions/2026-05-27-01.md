## Accomplished
- **B1 — schema field (`src/symbolic/supernode.rs`):**
  `pub delayed_capacity: usize` added to `Supernode`. Sentinel
  `usize::MAX` marks unbudgeted (legacy / fallback) supernodes.
- **B2 — capacity formula (`assign_delayed_capacities`):**
  ```
  tight    = max(K * own_ncol, FLOOR), K=4, FLOOR=16
  capacity = min(subtree_ncol(s) - own_ncol(s), tight)
  ```
  K=4 matches the empirical max delay-catchment ratio in
  `dev/research/per-front-delay-instrumentation-2026-05-27.md`
  (Phase A2.5 work). FLOOR=16 keeps small-n problems (e.g.
  MSS1_0000 n=163) out of the budget regime — the subtree
  worst-case still caps them. Subtree bound is the structural
  one-delay-per-subtree-col upper limit.
- **B3 — numeric-time enforcement (`src/numeric/factorize.rs`):**
  New `FeralError::DelayBudgetExceeded { supernode, required,
  capacity }` variant (MUMPS `INFO(2)` workspace-overflow analog).
  Triggered on budgeted, non-root supernodes when CB is disarmed
  and `n_delayed_in > delayed_capacity`. On budgeted paths with
  CB armed (the new default), the same condition engages the
  fallback at this supernode instead of erroring.
- **B4 — root-supernode width cap (`find_supernodes`):**
  `ROOT_CAP_MIN_N = 1024` guard, then decline merges that would
  push the root past `min(n/20, 2048)` columns. The guard
  preserves all existing small-matrix amalgamation tests.
- **B5 — CB rewire + default flip:**
  CB trigger is now `budget_exceeded` on budgeted supernodes
  (legacy ratio still drives the unbudgeted `usize::MAX` path

  `cascade_break_eps = Some(1e-10)` at all `NumericParams`
  construction sites.

## Abandoned Approaches
None this session — the plan executed end-to-end without dead
ends. Two minor corrections during implementation:
1. **First B4 attempt** used a flat `min(0.05*n, 2048)` cap with
   no `n` floor, which set the cap to 0 for small n=4 test
   matrices and broke `test_supernodes_tridiagonal_amalgamated`.
   Fixed by adding `ROOT_CAP_MIN_N = 1024` — cap only applies
   for problems large enough to warrant it.
2. **First B2 attempt** used `tight = K*own_ncol` with no
   absolute floor, which gave MSS1_0000 supernode 88 a capacity
   of 4 against an observed requirement of 6 and tripped
   `issue_15_cascade_arm_gate::small_n_disarms_cascade_break_trigger`.
   Fixed by adding `DELAY_CAPACITY_MIN_FLOOR = 16`.

Neither merits a `tried-and-rejected` entry — both were
intermediate calibration adjustments, not abandoned design paths.
